# 3.4 多 Agent 协作

## 为什么需要多个 Agent

一个 Agent 一次只能专注做一件事。当一个任务需要多个维度的分析时，用多个 Agent 并行处理比一个 Agent 串行快好几倍。

---

## 单 Agent vs 多 Agent

```
单 Agent（串行）：
审查代码正确性（5 分钟）
→ 审查安全性（5 分钟）
→ 审查性能（5 分钟）
→ 总计：15 分钟

多 Agent（并行）：
Agent 1：审查代码正确性（5 分钟）
Agent 2：审查安全性（5 分钟）        ← 同时跑
Agent 3：审查性能（5 分钟）
→ 汇总结果（1 分钟）
→ 总计：6 分钟
```

---

## Claude Code 的 Agent 工具

Claude Code 可以在对话中启动子 Agent：

```
你：审查这次的所有改动

Claude Code主Agent → 启动 3 个子Agent
├── 子Agent 1：找正确性 bug
├── 子Agent 2：找安全问题
└── 子Agent 3：找性能问题
       ↓
主Agent 汇总 3 个报告 → 输出给你
```

### 启动子 Agent 的方式

在 Claude Code 里，你可以直接说：
> "用 3 个子 Agent 并行审查代码：一个查 bug、一个查安全、一个查性能"

或者使用 `Workflow` 工具（编程方式编排多 Agent）。

## 什么时候需要多 Agent

### ✅ 适合多 Agent 的场景

| 场景 | 怎么分 |
|------|--------|
| **代码审查** | 正确性 Agent + 安全性 Agent + 性能 Agent |
| **大面积搜索** | 按目录或按内容分别搜索，汇总结果 |
| **多方案对比** | Agent 1 产方案 A，Agent 2 产方案 B，Agent 3 评判 |
| **批量迁移** | 每个 Agent 负责一部分文件的改写 |
| **测试生成** | 每个 Agent 负责一个模块的测试用例 |

### ❌ 不适合多 Agent 的场景

- 任务之间有顺序依赖（B 必须等 A 完成）
- 任务很小，启动 Agent 的开销比任务本身还大
- 你在一个会话的第 20 轮（上下文已经不够分给多 Agent 了）

---

## 多 Agent 的三种模式

### 模式 1：并行独立（最常用）
```
Agent 1 → 任务 A
Agent 2 → 任务 B    ← 各做各的，互不依赖
Agent 3 → 任务 C
```

### 模式 2：流水线
```
Agent 1 → 产出数据 → Agent 2 → 基于数据产出报告 → Agent 3 → 审查报告
```

### 模式 3：辩论
```
Agent 1 → 方案 A ┐
                  ├→ Agent 3（裁判）→ 选出最佳方案
Agent 2 → 方案 B ┘
```

---

## 多 Agent 的注意事项

### 1. 不要让他们改同一个文件
两个 Agent 同时编辑同一个文件 = 冲突。如果一个改了被另一个覆盖，你的代码就坏了。

### 2. 给每个 Agent 明确的边界
> "Agent 1 审查 src/api/ 下的所有文件，Agent 2 审查 src/services/ 下的所有文件"

每个 Agent 知道自己的范围，不会互相干扰。

### 3. 汇总比生成更重要
多 Agent 的瓶颈在**汇总阶段**——3 个 Agent 各自返回 2000 字报告，你怎么消化？**让主 Agent 做摘要**。

> "把 3 个 Agent 的报告汇总成一份不超过 500 字的结论，只保留高严重度发现"

### 4. Token 消耗翻倍
每个子 Agent 都是一次独立会话，有独立的上下文。3 个子 Agent 并行 = 大约 3 倍的 token 消耗。

---

## 实操：多 Agent 审查代码

```
你：用 3 个子 Agent 审查这次的所有改动文件。
    Agent 1：只找逻辑 bug（空指针、边界条件、竞态）
    Agent 2：只找安全问题（注入、泄露、越权）
    Agent 3：只找性能问题（N+1 查询、不必要的循环、大对象拷贝）
    每个 Agent 只输出高严重度的发现。
    最后汇总成一个表格，标注文件、行号、严重度。

Agent（主）：
| 文件 | 行号 | 类型 | 严重度 | 描述 |
|------|------|------|--------|------|
| auth.ts | 45 | 安全 | 🔴 高 | JWT secret 硬编码 |
| user.ts | 132 | 性能 | 🟡 中 | 循环内查询数据库 |
| api.ts | 78 | Bug | 🔴 高 | 未处理 null 返回值 |
```
