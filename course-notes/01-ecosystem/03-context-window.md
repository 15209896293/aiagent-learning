# 1.3 上下文窗口（Agent 的"记忆"）

## 设想一个场景

你和一个朋友在聊天。突然每说 10 句话，他就**彻底忘记**前面的内容。你会疯。

这就是 Agent 的处境。它的"记忆"叫**上下文窗口**，有硬上限。

---

## 上下文窗口是什么

**上下文窗口 = 模型一次能"看到"的最大文本量**

```
你发给模型的每一条消息
+ 模型的每一次回复
+ system prompt
+ 工具调用的输入输出
+ 读取的文件内容
─────────────────────────
= 当前上下文

上下文不能超过窗口上限。
一旦超过，必须丢弃最旧的内容。
```

上下文包含**整个对话的所有内容**，不只是你最后一条消息。

---

## 各模型上下文窗口

| 模型 | 窗口大小 | 相当于 |
|------|----------|--------|
| Claude 3.5/4.x | 200K tokens | ~150,000 英文单词，或 ~300 页书 |
| GPT-4o / GPT-5 | 128K tokens | ~100,000 英文单词 |
| Gemini 2.5 Pro | 2M tokens | ~150 万英文单词，整本书 |
| DeepSeek-V3/R1 | 128K tokens | ~100,000 英文单词 |

> ⚠️ 注意：这是"能塞进去"的上限，不是"能有效理解的"。窗口越大，模型在"大海捞针"时越容易遗漏信息。

---

## 上下文污染：为什么 Agent 聊着聊着就傻了

这是你每天都会遇到但没有意识到的现象。

### 污染机制

```
第 1 轮：你问 A → Agent 答 A
第 2 轮：你问 B → Agent 答 B（A 还在上下文里）
第 3 轮：你问 C → Agent 看到 A、B 的旧信息，开始混淆
...
第 20 轮：上下文里塞满了 19 轮对话 + 工具调用结果
         → Agent 开始"记忆衰退"
         → 给出不一致的答案
         → 重复之前说过的话
         → 忽略你刚发的指令
```

### 为什么会这样

模型的注意力机制在长上下文中会**稀释**——信息越多，每条信息的"权重"越低。最新消息权重最高，但旧信息不会消失，它们会干扰。

### 实际表现

- Agent 突然忽略了你上一轮说的话，用了 10 轮前的旧方案
- Agent 重复输出之前已经输出过的代码
- 你改了需求，但 Agent 按旧需求继续
- 越聊越累，感觉 Agent "不在状态"

### 怎么识别

如果你发现自己在说"我刚说了不要这个"，那就已经是上下文污染了。

### 怎么解决

- **开新会话**（最直接有效）
- 用 `/compact` 压缩 Claude Code 上下文（会生成摘要替代旧内容）
- 一个任务一个会话，别在一个会话里做十件事

## Prompt Caching：省钱机制

> ⚠️ 你的 DeepSeek API **不支持** Prompt Cache。但用 Claude 原生时支持。

### 什么是 Caching

```
请求 1：发送 "你是一个 Python 专家..." + "请帮我写一个排序函数"
        ↑ 系统提示词                  ↑ 实际任务

请求 2：发送 "你是一个 Python 专家..." + "请帮我写一个搜索函数"
        ↑ 这部分和请求 1 一样！
        → Cache 命中，这部分不收费
```

### 为什么重要

Claude API 中，Cache 命中的 token 价格只有原价的 **10%**。如果你在一个长会话里反复发送相同的 system prompt 和文件内容，Cache 能省很多钱。

### 你的情况

DeepSeek API → 没有 Cache，每轮请求都带着**全部上下文**重新计费。这意味着长会话非常烧钱。这就是为什么 CLAUDE.md 里有一条："一个任务一个会话"。

## 在你的工具里

| 工具 | 上下文管理方式 |
|------|----------------|
| Claude Code | 自动管理，但你可以 `/compact` 手动压缩。会话太长会提示 |
| Trae | IDE 自动裁剪旧对话，你看不到 |
| ZCode | 取决于实现，通常也是自动裁剪 |

**Claude Code 是你唯一能主动控制上下文的工具**——因为它让你看到文件被读入了上下文（绿色路径提示）。
