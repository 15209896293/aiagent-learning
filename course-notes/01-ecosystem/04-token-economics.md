# 1.4 Token 经济学

## Token 是什么

**Token ≠ 字。** Token 是模型处理文本的最小单位。

```
"Hello World"  → 2 个 token
"你好世界"     → 6 个 token（中文每个字 1-2 token）
"AI Agent"     → 2 个 token
"Tokenization" → 3 个 token（Token + ization）
```

规则：英文 1 个 token ≈ 0.75 个单词 ≈ 4 个字符。中文 1 个 token ≈ 1-2 个汉字。

## 一次请求到底花多少钱

### 案例 1：简单问题

```
问："用 Python 写一个 hello world"
发送：~50 tokens
回复：~150 tokens
─────────────────────────
DeepSeek-V3：(50*2 + 150*8)/1,000,000 ≈ ¥0.0013
Claude Sonnet：(50*3 + 150*15)/1,000,000 ≈ $0.0024
→ 几分钱
```

### 案例 2：代码审查（你的日常）

```
发送：整个文件 500 行代码 + prompt
     → ~3,000 tokens
回复：分析 + 建议 → ~2,000 tokens
─────────────────────────
DeepSeek-V3：(3000*2 + 2000*8)/1,000,000 ≈ ¥0.022
→ 2 分钱
```

### 案例 3：长会话 Agent 开发（真实案例）

```
对话 30 轮：每轮都带全部历史

累计发送 context：~90 万 tokens
累计回复：~30 万 tokens
─────────────────────────
DeepSeek-V3：(900K*2 + 300K*8)/1,000,000 ≈ ¥4.20
→ 单次会话 ¥4.2，一天 10 次就是 ¥42
```

**这才是真实成本。** 你的 CLAUDE.md 里有一条："曾一天消耗 2000 万 tokens"。2000 万 tokens × DeepSeek 价格 ≈ **¥60-120/天**。

## 为什么 Output 比 Input 贵

生成（Output）比理解（Input）更贵，因为：
1. 模型需要**逐词生成**，每生成一个词都要做一次完整的矩阵运算
2. 理解可以**并行处理**所有 input token
3. 生成是串行的，理解是并行的

## 烧钱的 4 个隐形杀手

### 1. 上下文累积（最隐蔽）
你的第 20 条消息，请求里带着前 19 轮的全部内容。即使你只问了"改一下第 3 行"，模型也要重新"读"完前面的 50,000 tokens。

### 2. 大文件反复读取
Agent 每次修改文件后重新读取验证 → 多消耗一倍 token。读一次就够了，相信工具返回的修改结果。

### 3. 错误重试
网络超时 → API 重试 → 整个请求 body 重发 → 双倍计费。看到 "Retrying..." 立即 Ctrl+C。

### 4. 工具调用开销
每次 Tool Call 的结果都塞进上下文。一个 Agent 循环调用 5 次 read_file，5 个文件的全部内容都在上下文里。2000 行的文件读了 4 次 → 8000 行 = ~20000 token。

## 省钱实操

| 策略 | 省多少 | 怎么做 |
|------|--------|--------|
| 一个任务一个会话 | 50-70% | 做完就开新的 |
| `/compact` | 30-50% | 上下文开始乱了就压缩 |
| 不要反复读同一个文件 | 20-40% | 记住已经读过的内容 |
| 选择合适的模型 | 80-90% | 简单任务用 Haiku 别用 Opus |
| 精简 prompt | 10-20% | 删掉客套话 |
