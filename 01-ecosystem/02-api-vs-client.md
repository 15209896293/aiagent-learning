# 1.2 API vs 客户端 vs IDE 插件

## 三层架构

```
┌──────────────────────────────────────────────┐
│                   你                          │
├────────────┬──────────────┬──────────────────┤
│  客户端     │  IDE 插件     │     API          │
│ (网页聊天)  │ (读你代码)    │   (纯代码调用)    │
├────────────┼──────────────┼──────────────────┤
│ ChatGPT    │ Claude Code  │ import anthropic │
│ Claude.ai  │ Cursor       │ import openai    │
│ DeepSeek   │ Trae         │ curl + Bearer    │
│ 网页       │ ZCode        │                  │
└────────────┴──────────────┴──────────────────┘
```

---

## 客户端（网页聊天）

### 能力
- 打字聊天，它回复
- 上传文件让它分析
- 记忆对话历史

### 做不到
- **读不了你的项目文件**（你得手动粘贴代码）
- **改不了你的文件**（它只能输出代码让你自己复制）
- **跑不了命令**（`npm install`？你想多了）
- **不知道你的项目结构**

### 什么时候用
- 问概念、学东西、讨论方案
- 写一段独立的小代码
- 翻译、润色、总结

**客户端是最弱的 Agent 形态——它只有"嘴"，没有"手"。**

---

## IDE 插件（Claude Code / Cursor / Trae / ZCode）

### 能力
- ✅ 读你整个项目的文件
- ✅ 改文件、创建文件、删除文件
- ✅ 执行终端命令（npm install、git commit）
- ✅ 搜索代码库
- ✅ 理解项目结构

### 原理
IDE 插件 = **模型 + 工具权限**。它本质上做了三件事：
1. 把你的问题 + 相关代码发给模型
2. 模型返回"我想读 X 文件"或"我想修改 Y"
3. 插件替模型执行这些操作，结果回传给模型

模型还是那个模型，但**插件给了它手**。

### 什么时候用
- 写新功能
- 调试 bug
- 重构代码
- 任何"需要读你项目"的场景

---

## API（直接调接口）

### 能力
- 最灵活：你自己写代码控制一切
- 可以用任何模型
- 可以自己定义工具（Tool Calling）
- 可以构建你自己的 Agent 应用

### 代价
- 你得写代码处理所有细节
- 你得管理 API Key、计费、重试、超时
- 你得自己实现上下文管理

### 什么时候用
- 构建有 Agent 功能的产品
- 自动化流程（批量处理、定时任务）
- 需要精细控制的场景

---

## 三者的本质区别

| | 客户端 | IDE 插件 | API |
|---|---|---|---|
| 能读你代码吗 | ❌ | ✅ | 取决于你怎么写 |
| 能改文件吗 | ❌ | ✅ | 取决于你怎么写 |
| 能跑命令吗 | ❌ | ✅ | 取决于你怎么写 |
| 灵活度 | 最低 | 中等 | 最高 |
| 上手难度 | 零 | 低 | 需要编程 |
| 你用的 | 偶尔 | **主力（Claude Code）** | 写 Demo 时 |

---

## 你该知道的

**Claude Code 是 IDE 插件层的极端形态**——它不是 GUI 的 IDE 插件，它是 CLI 的。这意味着：
- 没有按钮、没有侧边栏
- 你通过终端打字和它交流
- 它比 GUI 插件更灵活（能做的事更多）
- 但也更容易误操作（它可以跑任意命令）

**Trae 和 ZCode** 是更传统的 IDE 插件形态——在编辑器里有 UI 面板，可以选中代码让 AI 改。
