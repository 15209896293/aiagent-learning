第 6 课 · 用好 Cline

让 AI 在你的编辑器里替你写代码——真正的"打工模式"

Cline 到底是个什么东西？

Cline 是 VS Code 的扩展插件。装完之后，你的编辑器左边多一个聊天窗口——你告诉它要做什么，它直接动手：

你说"写个登录页"
→
它自动创建文件
→
写 HTML+CSS+JS
→
你实时看到结果

跟 Claude Code CLI 做的事情一样，但你在编辑器里能看到整个过程。

Cline vs Claude Code CLI · 什么时候用哪个？

Cline（VS Code 扩展）

• 在编辑器里直接改代码
• 你能实时看到文件变化
• 适合日常开发、页面制作
• 有文件树，不会"丢了"
• 可以设 auto-approve（不弹窗）

Claude Code CLI（终端）

• 纯终端操作，功能更全
• 有 worktree 隔离环境
• 适合大规模重构、复杂操作
• 有 MEMORY.md 跨会话记忆
• 权限控制更精细
建议：日常开发用 Cline（你能看到代码），遇到复杂任务切到 CLI。两个工具读同一份项目文件，互不冲突。

核心设置：让 Cline 不弹窗

你的痛点是"每次都弹窗确认"。Cline 可以设 Auto-Approve：

1 打开 Cline 设置（齿轮图标）

2 找到 "Auto-approve" 部分

3 勾选：读文件、写文件、执行命令（你信任的操作）

4 危险操作（删除、外部网络请求）保留手动确认

最佳实践：日常的文件读写放行，破坏性操作保留确认。既不被打断，也不失控。

.clinerules — Cline 的项目规则文件

在你的项目根目录下创建一个 .clinerules 文件，Cline 每次都会自动读取。就像 CLI 的 CLAUDE.md：

示例 .clinerules：
技术栈：React + TypeScript + Tailwind
命名规范：组件用 PascalCase，文件用 kebab-case
不要引入超过 5 个 npm 包
每次修改前先读相关文件
改完代码后运行 npm run dev 验证

现在动手

1. 在 VS Code 里装 Cline 扩展（已经装了就跳过）

2. 配置 API Provider → DeepSeek → 填入你的 API Key

3. Model 选 deepseek-chat（或 v4-pro）

4. 打开 F:\aiagent学习 文件夹

5. 创建 .clinerules，写一行：这是 AI 学习项目，用中文回答

6. 在 Cline 里说："你好，我在学习 AI Agent 开发"

检验标准：Cline 回复你一句话，说明配置成功。如果报错，把错误信息发给我。

这一课你带走的 3 个概念

1 Cline = VS Code 里的 AI 程序员，能直接改你的代码

2 Cline + CLI 配合 = 日常用 Cline，复杂用 CLI

3 .clinerules = 给 Cline 看的"员工守则"，自动生效
